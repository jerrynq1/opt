QUANTLAB SPOT STARTUP HOTFIX
============================

Problem
-------
The PWA activation path awaited expiry discovery before opening the Spot
WebSocket. Expiry discovery can perform multiple network requests and a bounded
90-day fallback scan, so Spot startup was unnecessarily serialized behind it.
The primary Worker relay also used a 12-second no-snapshot watchdog.

Changes
-------
1. Start the independent Spot WebSocket immediately when the GLD/QQQ Options
   view activates, before awaiting expiry discovery.
2. After expiry discovery completes, open only the option-chain WebSocket. Do not
   close/restart the already-running Spot socket.
3. Reduce the no-snapshot watchdog from 12s to 9s (three 3-second Price Stream
   snapshot intervals), while restarting its window when the Worker confirms
   that its Binance upstream is connected.
4. Record activation, socket-open, upstream-open, first-message and first-Spot
   timestamps; show first-Spot startup latency in Data Status diagnostics and
   expose the same fields through window.stockOptionsDebug().
5. Bump service-worker shell cache v23 to v24.

Data integrity
--------------
No Spot price is fabricated, no REST/option quote calculation is changed, and
Spot still uses the Binance Equity Price Stream payload. A last available price
received from Binance while the market is closed remains a valid observed price.

Validation
----------
Run ./test-all.sh from package root. Live Cloudflare/Binance/iOS timing still
requires a deployment smoke test on the user's device and network.
